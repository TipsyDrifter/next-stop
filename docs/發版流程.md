# 發版流程（v1.1.2 定案）

> 為什麼有這頁：v1.0／v1.1.0／v1.1.1 三次都是人手照決策記錄逐步敲，每次都重踩同一批坑。v1.1.2 起流程收進 `scripts/release.sh`，這頁只講「跑之前要備什麼」「一行指令」「腳本掛了怎麼人手接」。
> 拍板依據：v1.1.0 出爐時定的發版 SOP、v1.1 開工訪談第 9 條（安裝包進 `dist/`）、D-1.1-7（v1.1.2 發版定案）、D-1.1-8（release APK＋自簽 keystore）、v1.1.2 契約 §8。

## 一、前置（只要做一次；換機器才重做）

| 項目 | 怎麼確認 | 沒有會怎樣 |
|---|---|---|
| Windows 開發人員模式 | 設定 › 系統 › 開發人員選項 › 開啟 | `tauri android build` 在 symlink `.so` 那步炸（2026-09-16 踩到） |
| Node 22＋pnpm、Rust stable（含 `aarch64-linux-android` target） | `pnpm -v`、`cargo --version`、`rustup target list --installed` | 桌機／手機 build 起不來 |
| Android 工具鏈：JDK 17、SDK（build-tools 35）、NDK 28.2.13676358，全在 `%LOCALAPPDATA%\Android\{jdk17,Sdk,Sdk\ndk\…}` | `source scripts/android-env.sh` 印「已就緒」 | 路徑不對會直接報「找不到：…」；版本升級時改 `android-env.sh` 與 `android-env-cc.sh` |
| release 簽章 keystore：`%LOCALAPPDATA%\Android\keystore\{nextstop-release.jks, keystore.properties}`（主人保管，不進 repo） | 檔在即可；腳本只看檔有沒有，不讀內容 | gradle 退回 debug 簽章 → 腳本在 ⑤ 驗簽（CN 要含 `Next Stop`）時停；手機也裝不上（簽章不同不能覆蓋） |
| `gh` 已登入 | `gh auth status` | ① 前置檢查就停 |
| NSIS（Tauri 第一次 build 會自己抓） | — | WiX／MSI 不用：吃不下中文 productName |

## 二、一行指令

```bash
# 先寫 notes（沿 v1.1.1 的段落：主人會看到／這一版的邊界／安裝）
#   docs/release-notes/v1.1.2.md
bash scripts/release.sh 1.1.2 --notes docs/release-notes/v1.1.2.md
```

- 先 `--dry-run` 看一遍計畫（不改檔、不 build、不 push；git 髒也放行）：`bash scripts/release.sh 1.1.2 --dry-run`
- 只出桌機：加 `--skip-apk`
- 腳本做的事（每步印進度）：① 前置檢查 → ② bump `package.json`／`src-tauri/tauri.conf.json`／`src-tauri/Cargo.toml`＋`Cargo.lock`（離線）→ ③ commit「chore: 版號 X」＋`git tag vX` → ④ `CI=true pnpm tauri build --bundles nsis` → `dist/NextStop_X_x64-setup.exe` → ⑤ `pnpm tauri android build --apk --target aarch64`＋apksigner 驗簽 → `dist/NextStop_X_arm64.apk` → ⑥ `git push origin main vX`＋`gh release create vX 兩檔 --title vX --notes-file`
- 全程約 10–20 分鐘（Rust release 兩個 target 各重編一次；第一次拉 barcode-scanner 的 CameraX／ML Kit 會更久）。
- 憑證鐵則：腳本不讀 keystore 密碼、不印任何憑證；`dist/` 仍 gitignore，正本在 GitHub Release。

## 三、手動備援（腳本半路掛了）

腳本失敗會印出「在哪個階段」與對應回滾指令；照下表接手：

| 掛在 | 先回滾／狀態 | 人手接著做 |
|---|---|---|
| ① 前置 | 什麼都沒改 | 照訊息修（commit 髒檔、切 main、gh login、放 keystore） |
| ② bump | `git checkout -- package.json src-tauri/tauri.conf.json src-tauri/Cargo.toml src-tauri/Cargo.lock` | 通常是 `cargo metadata --offline` 缺快取：先連網跑一次 `cargo metadata` 再重跑腳本 |
| ③ commit／tag 之後、⑥ push 之前（④⑤ build 失敗） | `git tag -d vX && git reset --hard HEAD~1`（還沒 push，安全）；或保留 commit，修好 build 後從 ④ 人手做 | ④ `CI=true pnpm tauri build --bundles nsis` → `cp src-tauri/target/release/bundle/nsis/私鐵手帳_X_x64-setup.exe dist/NextStop_X_x64-setup.exe`；⑤ `source scripts/android-env.sh && pnpm tauri android build --apk --target aarch64` → `cp src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk dist/NextStop_X_arm64.apk`；再 `git push origin main vX` 與下一列 |
| ⑥ push 之後（gh release 失敗） | main 與 tag 已在遠端，不要退 | `gh release create vX dist/NextStop_X_x64-setup.exe dist/NextStop_X_arm64.apk --title vX --notes-file docs/release-notes/vX.md`；已建了 release 只是少檔 → `gh release upload vX <檔>` |
| 發完才發現包有問題 | — | 修好後出 X+1（patch），不刪 tag、不覆蓋既有 release 資產 |

驗簽（手動時也要做，debug 簽章裝不上主人手機）：
`source scripts/android-env.sh && "$ANDROID_HOME/build-tools/35.0.0/apksigner.bat" verify --print-certs dist/NextStop_X_arm64.apk` → 要看到 `CN=Next Stop, O=Kosa`。

## 四、雷區連結

- WiX 吃不下中文 productName → 只出 NSIS（2026-09-15 踩到）
- `tauri android build` 要開發人員模式（symlink）；GNU tar 解 zip 把 `C:` 當主機（2026-09-16 踩到）
- 小米裝 APK 要開「USB 安裝」且螢幕亮；`adb install` 覆蓋須同簽章（2026-09-16 踩到）
- GitHub Release 會剝掉中文檔名 → 產物一律改 `NextStop_X_…` 英文名：決策記錄〈v1.1.0 出爐〉發版流程
- Vite `outDir` 改 `build/`、`dist/` 專放安裝包：決策記錄〈v1.1 開工訪談拍板〉9
- 簽章私鑰進 repo＝任何人都能簽假更新 → keystore 只在 `%LOCALAPPDATA%\Android\keystore\`，備份在 `files/secrets/`（gitignore）：D-1.1-8
- 升級後桌機第一趟 pull 會整批收進手機在 v1.1.1 期間累積的 outbox（預期行為）：v1.1.2 契約席回報
