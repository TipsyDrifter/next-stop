# 發版流程

> 這頁講四件事：發版前要準備什麼（含換新電腦從零重建、Android 簽章鑰匙的備份與救援）、一行指令發版、腳本半路掛了怎麼手動接、踩過的坑。發版的每一步都寫在 `scripts/release.sh` 裡，`--dry-run` 會把要跑的指令全部印出來；這頁只補腳本自己說不清楚的部分。

## 一、事前準備（只要做一次；換電腦才要重做）

| 項目 | 怎麼確認 | 沒有會怎樣 |
|---|---|---|
| Windows 開發人員模式 | 設定 › 系統 › 開發人員選項 › 開啟 | `tauri android build` 在 symlink `.so` 那一步會失敗 |
| Node 22＋pnpm、Rust stable（含 `aarch64-linux-android` target） | `pnpm -v`、`cargo --version`、`rustup target list --installed` | 桌機、手機都 build 不起來 |
| Android 工具鏈：JDK 17、SDK（platform 36、build-tools 35）、NDK 28.2.13676358，全放在 `%LOCALAPPDATA%\Android\{jdk17,Sdk,Sdk\ndk\…}`；怎麼裝見下面〈換新電腦重建環境〉 | `source scripts/android-env.sh` 印出「已就緒」 | 路徑不對會直接報「找不到：…」；升級版本時改 `android-env.sh` 和 `android-env-cc.sh` |
| release 簽章用的 keystore：`%LOCALAPPDATA%\Android\keystore\{nextstop-release.jks, keystore.properties}`（不進 repo）；**離機備份與遺失救援見下面〈簽章 keystore〉** | 檔案在就好；腳本只看檔案在不在，不讀內容 | gradle 會退回 debug 簽章 → 腳本在 ⑤ 驗簽（CN 要含 `Next Stop`）時停下；手機也裝不上（簽章不同不能覆蓋） |
| `gh` 已登入（要能 push 私有的 `TipsyDrifter/next-stop-dev` 和鏡像 `TipsyDrifter/next-stop`） | `gh auth status` | ① 前置檢查就會停 |
| NSIS（Tauri 第一次 build 會自己下載） | — | 不用 WiX／MSI：它吃不下中文的 productName |

### 換新電腦重建環境

照順序做。Android 工具鏈不需要 Android Studio，全部裝在 `%LOCALAPPDATA%\Android\`（`scripts/android-env.sh` 預設找這裡），下載約 3.5 GB。

**① 基礎工具。** 先到〔設定 › 系統 › 開發人員選項〕打開開發人員模式，再在 PowerShell 跑（`winget` 第一次用會請你同意來源條款）。細節以 Tauri 官方的 [Prerequisites](https://v2.tauri.app/start/prerequisites/) 為準：

```powershell
winget install -e --id Git.Git
winget install -e --id OpenJS.NodeJS.LTS
winget install -e --id GitHub.cli
winget install -e --id Rustlang.Rustup
winget install -e --id Microsoft.VisualStudio.2022.BuildTools --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

裝完**開一個新的終端機視窗**（讓 PATH 生效），之後全部在 Git Bash 裡做：

```bash
npm install -g pnpm
rustup default stable
gh auth login                                   # 用 TipsyDrifter 帳號
gh repo clone TipsyDrifter/next-stop-dev && cd next-stop-dev
pnpm install
git ls-files --eol src-tauri/migrations         # 每列都要是 w/lf；有 w/crlf 先別 build（見〈踩過的坑〉）
```

**② Android 工具鏈。** 在專案根目錄跑（JDK 用 Eclipse Temurin 17；command-line tools 檔名裡的數字會隨新版變，失效時到 <https://developer.android.com/studio> 頁底「Command line tools only」換成最新的 Windows 版網址）：

```bash
A="$(cygpath -u "$LOCALAPPDATA")/Android"; mkdir -p "$A/_dl" "$A/Sdk/cmdline-tools"
(cd "$A/_dl" &&
  curl -L -o jdk17.zip "https://api.adoptium.net/v3/binary/latest/17/ga/windows/x64/jdk/hotspot/normal/eclipse" &&
  /c/Windows/System32/tar.exe -xf jdk17.zip && mv jdk-17* "$A/jdk17" &&
  curl -L -o clt.zip "https://dl.google.com/android/repository/commandlinetools-win-15859902_latest.zip" &&
  /c/Windows/System32/tar.exe -xf clt.zip && mv cmdline-tools "$A/Sdk/cmdline-tools/latest")
export JAVA_HOME="$(cygpath -w "$A/jdk17")"; SDKM="$A/Sdk/cmdline-tools/latest/bin/sdkmanager.bat"
yes | "$SDKM" --sdk_root="$(cygpath -w "$A/Sdk")" --licenses
"$SDKM" --sdk_root="$(cygpath -w "$A/Sdk")" "platform-tools" "platforms;android-36" "build-tools;35.0.0" "ndk;28.2.13676358"
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
source scripts/android-env.sh                   # 印「Android 建置環境已就緒（JDK 17、NDK 28.2.13676358）」才算好
```

- 版本跟著 `src-tauri/gen/android` 走：所有模組都是 `compileSdk = 36`，NDK 版本寫在 `android-env.sh`。`sdkmanager` 會印一段「已被 Android CLI 取代」的警告，不影響使用。
- 解 zip 一定用 `C:\Windows\System32\tar.exe`：Git Bash 自帶的 GNU tar 會把 `C:` 當成遠端主機。
- **不要跑 `tauri android init`**：`src-tauri/gen/android` 已經在 repo 裡而且改過（AndroidManifest、MainActivity、簽章設定），init 會把它們重生成模板。

**③ 簽章 keystore 放回去**：照下一段〈放回新電腦〉。

**④ 驗收**：`bash scripts/release.sh <下一個版號> --dry-run`。① 裡看到「✓ 已發行 migration 表 N/N 對齊」「✓ keystore.properties 在」「✓ 前置檢查通過」，②–⑥ 印出要跑的指令，就可以發版了（它不改檔、不 build、不 push）。

### 簽章 keystore：離機備份與遺失救援

Android 只讓**同一把鑰匙簽的 APK** 覆蓋升級已經裝好的 App。這把鑰匙只有發版這台電腦上有；repo 裡 `files/secrets/android-keystore/` 那份（gitignore、不進版控）跟正本在同一台電腦、同一顆碟，電腦一壞兩份一起沒。所以要在**別的地方**再放一份。

| 檔案 | 位置 | 內容 |
|---|---|---|
| `nextstop-release.jks` | `%LOCALAPPDATA%\Android\keystore\` | 簽章鑰匙本體（PKCS12，別名 `nextstop`），沒有密碼打不開 |
| `keystore.properties` | 同上 | 給 gradle 讀的四行：鑰匙檔的絕對路徑、`storePassword`、`keyAlias`、`keyPassword`（**密碼是明文**） |

這把鑰匙簽出來的憑證是 `CN=Next Stop, O=Kosa`，有效到 2054-02-01，SHA-256 指紋：
`BB:4C:D1:DE:E9:88:CE:B2:9C:2D:9A:72:6F:47:2A:84:34:88:08:A7:AA:1A:90:29:E5:54:05:C0:74:9E:03:79`

**離機備份**（做一次；換了鑰匙就重做）。鑰匙檔和密碼**分開放**——只撿到其中一樣的人簽不出假更新：

1. 鑰匙檔複製到隨身碟或雲端硬碟。在 PowerShell 跑（`E:\NextStop 簽章備份` 換成你的隨身碟或雲端硬碟資料夾）：
   ```powershell
   New-Item -ItemType Directory -Force "E:\NextStop 簽章備份" | Out-Null
   Copy-Item "$env:LOCALAPPDATA\Android\keystore\nextstop-release.jks" "E:\NextStop 簽章備份\"
   ```
2. 密碼存進密碼管理器：`notepad "$env:LOCALAPPDATA\Android\keystore\keystore.properties"`，把 `storePassword`、`keyPassword`（還有 `keyAlias=nextstop`）抄成一則安全筆記。`keystore.properties` 含明文密碼，別把它放進存鑰匙檔的那個資料夾；如果你有整個資料夾自動上雲端的備份，也確認一下它沒有連 `files\secrets\` 一起帶上去。
3. 驗一次備份的是對的那把：下面這行會問密碼，輸入 `storePassword`，看到的 `SHA256:` 要跟上面那串一樣。
   ```powershell
   & "$env:LOCALAPPDATA\Android\jdk17\bin\keytool.exe" -list -v -keystore "E:\NextStop 簽章備份\nextstop-release.jks" -alias nextstop
   ```

**放回新電腦**：把 `nextstop-release.jks` 放進 `%LOCALAPPDATA%\Android\keystore\`，在同一個資料夾新建 `keystore.properties`。`storeFile` 是絕對路徑，新電腦的使用者名稱不同就改那一段：

```properties
storeFile=C:/Users/<你的 Windows 使用者名稱>/AppData/Local/Android/keystore/nextstop-release.jks
storePassword=<密碼管理器裡的 storePassword>
keyAlias=nextstop
keyPassword=<密碼管理器裡的 keyPassword>
```

腳本只檢查這個檔在不在；密碼打錯會在 ⑤ build 時失敗。第一次發版 ⑤ 驗簽看到 `CN=Next Stop, O=Kosa` 才算真的接上。

**鑰匙遺失了會怎樣**

- 桌機不受影響：Windows 安裝檔沒有簽章這一關。
- 手機上已經裝好的 App **從此不能再升級**：新鑰匙簽的 APK，Android 會拒絕覆蓋（`adb install -r` 回 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，手動點 APK 會說安裝失敗或跟現有的套件衝突）。
- 剩兩條路：
  - **換新鑰匙、手機解除安裝後重裝（建議）**：手機上的資料靠同步拿回來。代價是手機上還沒同步出去的修改，以及各台自己記的設定（主題、時刻表通知與釘選）要重來。
  - **換套件名讓新舊並存**：不用解除安裝，但手機上會出現兩個私鐵手帳、分享選單與通知各兩份，新的那個對同步來說是一台全新的裝置，舊的最後還是要手動刪；套件名又跟 Tauri identifier 綁在一起（`src-tauri/tauri.conf.json`），改它會牽動桌機的資料資料夾。不建議。

**救援步驟（換新鑰匙）**

1. 手機還能開就先保住資料：打開 App，按「立即同步」、再按「立即備份到雲端」（同步頁的雲端備份區），確認都成功。手機沒加入同步的話，先按「匯出到手機」存一份 JSON（App 匯不回來、只能人工翻，所以能加入同步就先加入）。
2. 產一把新鑰匙（PowerShell；會問兩次密碼，PKCS12 的鑰匙密碼就是同一組）。CN 一定要含 `Next Stop`，`release.sh` ⑤ 驗簽靠它認：
   ```powershell
   New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\Android\keystore" | Out-Null
   & "$env:LOCALAPPDATA\Android\jdk17\bin\keytool.exe" -genkeypair -v -keystore "$env:LOCALAPPDATA\Android\keystore\nextstop-release.jks" -alias nextstop -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Next Stop, O=Kosa"
   ```
3. 照〈放回新電腦〉寫好 `keystore.properties`（兩個密碼填同一組），照〈離機備份〉重做一次，並把這頁上面的 SHA-256 指紋與有效期換成新的。
4. 照常發版（〈二、一行指令〉）。
5. 手機：解除安裝舊的私鐵手帳（或 `adb uninstall app.shitetsu.nextstop`）——**這一步會清掉手機上的資料**，所以第 1 步要先做完。裝上新的 APK，打開〔更多 › 同步〕「加入同步」：雲端有資料、這台是空的，會直接拉下來（忘了密語就用復原碼）。配對碼可以在桌機〔設定 › 同步〕「顯示配對碼」掃。

### 共用編譯快取 `C:\build`（選配）

這台電腦在 `%USERPROFILE%\.cargo\config.toml` 設了一行機器級的 cargo 設定，把所有 Rust 專案的中間產物集中到 `C:\build`（每個專案、每個 worktree 依路徑各一格）：

```toml
[build]
build-dir = "C:/build/{workspace-path-hash}"
```

- 它只是**快取**，空間吃緊時整個 `C:\build` 刪掉也沒關係，下次 build 會重新產生（那一次會全量重編、比較慢）。只刪久沒動的格子：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prune-build-cache.ps1 -DryRun` 先看，拿掉 `-DryRun` 才真的刪。
- 最終產物（exe、安裝檔）照樣在 `src-tauri/target/` 底下，下面幾節寫的路徑不受影響。
- 新電腦不設也能 build（中間產物就留在 `src-tauri/target/`）；要設就照上面那三行寫進新電腦的 `%USERPROFILE%\.cargo\config.toml`。

## 二、一行指令

```bash
# 先寫 notes（段落沿用 v1.1.1：主人會看到／這一版的邊界／安裝）
#   docs/release-notes/v1.1.2.md
bash scripts/release.sh 1.1.2 --notes docs/release-notes/v1.1.2.md
```

- 先用 `--dry-run` 看一遍計畫（不改檔、不 build、不 push；git 不乾淨也照跑）：`bash scripts/release.sh 1.1.2 --dry-run`
- 只出桌機：加 `--skip-apk`
- 腳本做的事（每一步都會印進度）：① 前置檢查 → ② 改版號：`package.json`／`src-tauri/tauri.conf.json`／`src-tauri/Cargo.toml`＋`Cargo.lock`（離線）→ ③ commit「chore: 版號 X」＋`git tag vX` → ④ `CI=true pnpm tauri build --bundles nsis` → `dist/NextStop_X_x64-setup.exe` → ⑤ `pnpm tauri android build --apk --target aarch64`＋apksigner 驗簽 → `dist/NextStop_X_arm64.apk` → ⑥ `git push origin main vX`＋`gh release create vX 兩檔 --title vX --notes-file`
- **發完私有 repo 之後，鏡像要另外發一行**（兩步都要帶 `--release`，否則只推程式碼、鏡像的 Release 頁會停在上一版）：`bash scripts/mirror-publish.sh --tag vX --release --notes docs/release-notes/vX.md`；發完 `gh release list --repo TipsyDrifter/next-stop --limit 1` 看到 vX Latest 才算完。
- 全程大約 10–20 分鐘（Rust release 兩個 target 各重編一次；第一次拉 barcode-scanner 的 CameraX／ML Kit 會更久）。
- 憑證的規則：腳本不讀 keystore 密碼、不印任何憑證；`dist/` 照樣在 gitignore 裡，正本在 GitHub Release。

## 三、腳本半路掛了怎麼手動接

腳本失敗時會印出「卡在哪個階段」和對應的回滾指令，照下表接手：

| 卡在 | 先回滾／目前狀態 | 接下來手動做 |
|---|---|---|
| ① 前置 | 什麼都還沒改 | 照訊息修（commit 沒提交的檔、切到 main、gh login、放好 keystore） |
| ② 改版號 | `git checkout -- package.json src-tauri/tauri.conf.json src-tauri/Cargo.toml src-tauri/Cargo.lock` | 通常是 `cargo metadata --offline` 缺快取：先連網跑一次 `cargo metadata`，再重跑腳本 |
| ③ commit／tag 之後、⑥ push 之前（④⑤ build 失敗） | `git tag -d vX && git reset --hard HEAD~1`（還沒 push，安全）；或保留 commit，修好 build 後從 ④ 手動做 | ④ `CI=true pnpm tauri build --bundles nsis` → `cp src-tauri/target/release/bundle/nsis/私鐵手帳_X_x64-setup.exe dist/NextStop_X_x64-setup.exe`；⑤ `source scripts/android-env.sh && pnpm tauri android build --apk --target aarch64` → `cp src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk dist/NextStop_X_arm64.apk`；再 `git push origin main vX`，接著做下一列 |
| ⑥ push 之後（gh release 失敗） | main 和 tag 已經在遠端，不要退 | `gh release create vX dist/NextStop_X_x64-setup.exe dist/NextStop_X_arm64.apk --title vX --notes-file docs/release-notes/vX.md`；release 已經建了只是少檔 → `gh release upload vX <檔>` |
| 發完才發現安裝包有問題 | — | 修好後出 X+1（patch），不刪 tag、不覆蓋已經發出去的 release 檔案 |

驗簽（手動時也要做，debug 簽章的 APK 裝不上已經裝了正式版的手機）：
`source scripts/android-env.sh && "$ANDROID_HOME/build-tools/35.0.0/apksigner.bat" verify --print-certs dist/NextStop_X_arm64.apk` → 要看到 `CN=Next Stop, O=Kosa`。

## 四、踩過的坑

- WiX 吃不下中文 productName → 只出 NSIS（2026-09-15 踩到）
- `tauri android build` 要開開發人員模式（symlink）；GNU tar 解 zip 會把 `C:` 當成主機（2026-09-16 踩到）
- 小米裝 APK 要開「USB 安裝」，而且螢幕要亮；`adb install` 覆蓋安裝必須是同一個簽章（2026-09-16 踩到）
- 手機走無線 adb：裝機前先 `adb mdns services`＋`adb devices -l` 找裝置，序號每次現抓（mDNS 名稱會變）；找不到隔 30 秒再看，兩三次還是沒有，就請使用者在手機的開發人員選項打開無線偵錯
- GitHub Release 會把中文檔名剝掉 → 產物一律改成 `NextStop_X_…` 的英文檔名：決策記錄 v1.1.0 發布那一節的發版流程
- Vite 的 `outDir` 改成 `build/`，`dist/` 專門放安裝包：決策記錄 v1.1 開工訪談那一節第 9 條
- 簽章私鑰進 repo＝任何人都能簽假更新 → keystore 只放在 `%LOCALAPPDATA%\Android\keystore\`，repo 內的複本在 `files/secrets/`（gitignore），離機備份照〈簽章 keystore〉那段做：D-1.1-8
- 已發行的 migration（`src-tauri/migrations/*.sql`）一個位元組都不能改，行尾也算：使用者資料庫記著每支的校驗碼，對不上就拒開。`.gitattributes` 鎖了 LF，`release.sh` ① 也會核對已發行表；新 clone 或開 worktree 後先跑 `git ls-files --eol src-tauri/migrations` 確認每列都是 `w/lf`
