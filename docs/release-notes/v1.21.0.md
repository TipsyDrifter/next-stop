# v1.21.0 · 同步引擎：兩台併發的接縫一次補完

同步引擎的收斂語義大修。兩輪累積下來的「兩台同時動同一筆」接縫（#84／#86／#96／#97／#99／#101／#103＋B2 系列）一次定策略、一次修完。**這一版帶兩支新的資料庫 migration（0012／0013）——兩台請一起升級**（舊版混用期間，另一台在新版改的逐班時刻會等它也升級後才看得到）。

## 主人會看到
- **兩台各改同一張定期券的不同班次，兩邊都保得住**：逐班時刻改成一班一筆各自同步，不再整欄互蓋（以前後改的那台會把另一台的改動吃掉）。真的撞到同一班時，提示會講清楚是「哪張票幾月幾號那班」，不再籠統地說「本班時刻兩台都改過」。
- **荷札改名跟到底**：一台把 #X 改名 #Y、另一台同時還在用 #X 掛東西——同步後掛的東西自動跟到 #Y，不再留下一枚空殼讓時段排除悄悄失效；提示說「#X 已改名為 #Y，掛在上面的東西跟過去了」，不再誤報「你刪掉的荷札回來了」。改名後刻意重建一枚新的 #X 也沒問題，新舊井水不犯河水。
- **帳戶／分類的順序不再合成「不是任何一台的版本」**：兩台各自排同一組，同步後會收斂成其中一台排的完整順序（售票口帳戶、帳目分類、時刻表分類都是）。
- **「改用另一台的資料」先探路再動手**：對方的資料是較新版 App 寫的時，現在會在清掉本機之前就擋下來、本機一根毛都不動（以前是先清空才發現套不上）；改正待ち的「改用那份」同樣受保護。
- **退役定期券的執行日兩台一致**：連同列車一起完成的定期券，執行日一律顯示「最後跑的那一班」，兩台不再各說各話（以前一台會在隔天的今日頁多出一張済）。
- **其他收斂**：加入同步途中關掉 App，重開後會自動續拉（不再停在「已加入但暫停」）；兩台同時刪同一筆，不再各留各的刪除時刻；換鑰匙那台中途死掉時，別台日常同步會順手把舊鑰匙的舊紀元清掉（真撤銷不再卡住）；目標分類被另一台蓋掉時，同步清單會列出這台原本多／少了哪些分類。

## 底下換了什麼
- 新表 `node_time_overrides`（migration 0012）：逐班時刻一班一列，沿用引擎現成的逐列收斂；既有資料開 App 後自動搬，兩台各搬一次、結果一致。
- 荷札多了「改名去向」欄（migration 0013）：同步後的整理把復活空殼上的掛載轉到新名；親手重建同名荷札會清掉去向。
- 時鐘防護：收到超過 24 小時的未來時間戳不再納入本機時鐘種子（一台時鐘飛掉不會拖著全家跑）。
- 以上語義全部經雙機沙盒（獨立 identifier＋獨立雲端根）實測，三台重播情境另驗。

## 這一版的邊界
- 並行「新增一列 × 整組重排」仍可能撞順序號，由建立時間決勝（畫面不跳、兩台一致）。
- 路線圖大綱（nodes）的排序不在這次範圍（等 fractional index 那題一起定）。
- 已經寫進資料的超限時間戳照認（只擋擴散，不回頭改史）。
- 仍需自己的 Cloudflare R2（自用階段）。
